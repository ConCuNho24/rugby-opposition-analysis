# Data acquisition and profiling

## Selected public source

The PoC acquires the public Rugby Union scoring data from
[transientlunatic/Rugby-Data](https://github.com/transientlunatic/Rugby-Data).
The downloader uses this pinned raw source rather than a moving branch:

```text
https://raw.githubusercontent.com/transientlunatic/Rugby-Data/90923144567e1613a3d941ba72a54a10a3866194/json/premiership-2024-2025.json
```

The selected repository did not expose an explicit licence during project
research. Treat this as attributed, non-production course research only. Do not
commit, republish, distribute or use the raw source commercially without
permission from the data owner.

## Prerequisites

- Python 3.11 or later.
- An internet connection for the initial download.
- Permission to access GitHub from the local network.

Install project packages from the project root before running the scripts:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

If PowerShell blocks activation, use a session-only policy change and activate
again:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

On macOS/Linux, replace the activation command with:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

## Download the source

From the project root, run:

```powershell
python scripts/download_data.py
```

The script:

1. downloads the pinned season JSON;
2. saves the original file under
   `data/raw/rugby_data_premiership_2024_2025/source/`;
3. saves one source-record JSON per match under
   `data/raw/rugby_data_premiership_2024_2025/matches/`; and
4. writes a local provenance/hash manifest at
   `data/raw/rugby_data_premiership_2024_2025/source_manifest.json`.

Use the following only when deliberately refreshing the pinned raw files:

```powershell
python scripts/download_data.py --force
```

`--force` rewrites local raw files from the same pinned URL. It does not upgrade
the selected source revision; changing the revision is a documented project
decision, not a routine runtime action.

## Network-restricted manual setup

Do not replace the source with arbitrary JSON. If GitHub access is blocked, have
a permitted machine run the normal downloader and copy this complete directory
to the identical path in the project:

```text
data/raw/rugby_data_premiership_2024_2025/
  source/premiership-2024-2025.json
  matches/*.json
  source_manifest.json
```

The processing and UI steps can then run locally without external data access.
Keep the copied directory out of Git and retain the manifest so its provenance is
auditable.

## Profile before analysis

Run:

```powershell
python scripts/profile_data.py
```

This produces `outputs/data_profile.json`. Check it before interpreting any
report. It records:

- source fields and source score-event types;
- files/matches found and canonical event count;
- real team and player availability;
- timestamp range and missing timestamp count;
- coordinates/period/play-by-play availability; and
- sample source-match headers.

The profile is intentionally explicit that no coordinate, possession, complete
play-by-play, tackle/carry/line-break or verified period field is available in
the selected data.

## Expected directory ownership

| Path | Purpose | Version-control treatment |
| --- | --- | --- |
| `data/raw/` | Downloaded public source, split source records and provenance manifest | Ignored; source data are reproducible but not redistributed. |
| `data/processed/` | Per-match canonical CSVs and combined canonical store | Ignored; regenerated by the pipeline. |
| `data/state/processing_manifest.json` | Content-hash cache for incremental processing | Ignored; regenerated by the pipeline. |
| `outputs/` | Profile, charts and HTML reports | Ignored; regenerated by scripts/UI. |
| `data/synthetic/` | Tiny reformatted architecture-test fixture only | Tracked, clearly labelled; never mixed into real outputs. |
